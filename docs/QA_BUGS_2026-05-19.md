### Positive findings (no bug)

- SQL-injection-y path params (e.g. `/accounts/1 OR 1=1`) → 404 / route mismatch, never reach the DB.
- `<script>` payload in `/credit-lines/payments?nickname=<script>...` is rendered as text in the input value, not executed (see `76-receivables-xss.png`).

## Test login

`routes/web.php` (dev/local only) now accepts:

```
GET /dev-login                                      → claude@test.local (no roles)
GET /dev-login/{redirect-path}                      → claude@test.local then redirect to /{redirect-path}
GET /dev-login?as=<email>                           → log in as that email
GET /dev-login?as=<role-alias>                      → role aliases:
     admin | system-admin → admin@dev.familyfund.local
     fund-admin           → qa-fund-admin@test.local
     financial-manager    → qa-financial-manager@test.local
     beneficiary          → qa-beneficiary@test.local
```

Examples:

```
curl -L "http://localhost:3020/dev-login/dashboard?as=fund-admin"
curl -L "http://localhost:3020/dev-login/funds/2/overview?as=admin"
```

The `qa-*@test.local` users are scoped to fund id 2 (Family Fund A) and use
password `password`.

### #2 — `/credit-lines/{id}` 500 (FIXED by running the backfill migration on dev)

```bash
# Pre-migration: 500 QueryException, "credit_line_payment_allocations doesn't exist".

# Run the pending backfill:

curl -si -c /tmp/cj -b /tmp/cj -L \
  "http://localhost:3020/dev-login/credit-lines/2?as=admin" | head -1
```
