### Positive findings (no bug)

- `Cancel` is correctly blocked with a flash error "Cannot cancel credit
  line: 120.0000 shares still outstanding. Pay off the line before
  cancelling." when called with `outstanding > 0` via the documented endpoint
  (see **#4** for the baseline data hole).
- Fund-level invariants (`sharesAsOf`, `shareValueAsOf`, `valueAsOf`) are
  **unchanged** by opening / repaying / overpaying CLs — `creditLineReceivableValueAsOf`
  is the only fund metric that moves, which is the correct partition.
- Negative shares (`shares=-50`) are rejected by validation before any
  transaction is written.
- Repay on a `status='paid_off'` line is blocked with a clear flash
  ("Cannot repay a credit line with status \"paid_off\". Only active lines
  accept repayments.").

### Regression #1 — `repay` enforces shares ≤ outstanding (or cascades)

```
- Seed: a fund + an account + an active CL with principal=100, outstanding=100.
- Call the repay endpoint with shares=150.
- Assert either:
    a) HTTP 422 / redirect with validation error AND
       transactions table has no new REP row, OR
    b) the CL row is paid_off with outstanding=0, exactly one new REP row

- A second case: account has two active CLs (A=100 outstanding, B=50 outstanding).
  Call repay(A, shares=140). If cascade is the chosen semantics: A paid_off,
  B outstanding=10, two REP rows totalling 140 with cl_id linkage.
```

### Regression #2 — `repay` rejects dates outside [origination_date, today]

```
- Active CL originated 2026-01-01, term 12 months, outstanding=100.

  - date='2025-12-31'  -> 422, no REP row
  - date='2026-01-01'  -> 200, REP recorded

- Assert account_balances has no rows with start_dt > NOW(); transactions
  has no rows with timestamp > NOW().
```
